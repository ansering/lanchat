# 开发与测试要求及方案

> 规定 LAN Chat 的开发要求、质量门、测试策略、用例与验收标准。
> 与 `DEVELOPMENT.md` 配套，作为执行层的检查依据。

## 1. 开发环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10/11 或 Windows Server |
| 工具链 | 仓颉 SDK（`cjc`、`cjpm`）+ Visual Studio 生成工具 |
| 依赖 | stdx（net、encoding.json）已在 `cjpm.toml` 声明 |
| 编辑器 | 支持仓颉语言服务（可选） |
| 版本控制 | Git |
| 验证 | `cjc --version`、`cjpm --version` 可用，官方示例跑通 |

## 2. 开发要求

### 2.1 代码规范

- 一个文件一件事；函数建议 ≤ 50 行，文件建议 ≤ 约 400 行。
- 命名：类型 `UpperCamel`、函数/变量 `lowerCamel`、常量 `ALL_CAPS`、文件名小写下划线。
- 提交前必须 `cjfmt`、`cjlint`。
- 不引入未使用的依赖与死代码。

### 2.2 并发要求

- 所有对 `users/sessions/rooms` 的访问必须在 `synchronized(gLock)` 内。
- 所有 socket 写必须在 `synchronized(session.writeLock)` 内。
- 锁顺序固定为 `gLock → writeLock`。
- 严禁在持锁期间做阻塞 I/O；`broadcast` 先收集目标再发送。
- 客户端打印统一走 `outLock`。

### 2.3 协议要求

- 协议变更必须先更新 `DEVELOPMENT.md` §5，再改 `protocol.cj`。
- 所有 JSON 字段访问必须经 `protocol.cj` 的辅助函数，禁止散落硬编码。
- 新增消息类型必须同时新增校验、处理与测试。

### 2.4 安全要求

- 密码必须加盐哈希存储，禁止明文。
- 严格按 §5.9 校验输入，拒绝非法/超长输入。
- 错误信息不泄露内部堆栈。

### 2.5 质量门

| 门 | 标准 |
|---|---|
| G1 格式 | `cjfmt -w src` 无改动 |
| G2 静态检查 | `cjlint src` 无严重告警 |
| G3 编译 | `cjpm build` 通过 |
| G4 单元测试 | `cjpm test` 全绿 |
| G5 评审 | 通过 §10 评审清单 |

## 3. 测试策略

| 层次 | 目标 | 手段 | 执行频率 |
|---|---|---|---|
| 单元测试 | 协议、校验、哈希、房间逻辑 | `std.unittest` | 每次提交 |
| 集成测试 | 端到端消息流 | 脚本客户端 / 多进程 | 每迭代 |
| 验收测试 | FR/NFR 全量 | 手工多终端 + 检查表 | 发布前 |
| 联调测试 | 真实 WiFi 环境 | 三台电脑 | 发布前 |

### 3.1 进入 / 退出条件

| 阶段 | 进入条件 | 退出条件 |
|---|---|---|
| 单元测试 | 代码可编译 | 全部用例通过 |
| 集成测试 | 最小系统可运行 | IT-01~IT-09 通过 |
| 验收测试 | 功能开发完成 | 验收清单无未通过项 |
| 联调测试 | 单机验收通过 | 三机 WiFi 场景通过 |

## 4. 单元测试用例

| 编号 | 目标 | 输入 | 预期 |
|---|---|---|---|
| UT-01 | `encode` | `ok(register)` | 以 `\n` 结尾的合法 JSON |
| UT-02 | `decode` | 合法一行 | 返回对象且含 `type` |
| UT-03 | `decode` | `{bad` | 返回 `None` / 不抛未捕获异常 |
| UT-04 | `readLine` | 超 64 KiB 一行 | 触发错误码 1006 语义 |
| UT-05 | `sha256Hex` | 同盐同密码 | 结果一致且非空 |
| UT-06 | 登录校验 | 错误密码 | 校验失败 |
| UT-07 | `validUsername` | `ab` / `a b` / `a#b` | 均拒绝 |
| UT-08 | `validRoom` | 空 / 含空格 / 超长 | 均拒绝 |
| UT-09 | `validText` | 空 / 纯空白 / 超长 | 均拒绝 |
| UT-10 | `splitFirst` | `bob hello world` | `("bob","hello world")` |

运行：`cjpm test`

## 5. 集成测试用例

| 编号 | 前置 | 步骤 | 预期 |
|---|---|---|---|
| IT-01 | 服务端运行 | A 注册并登录 | 收到 `login_ok` |
| IT-02 | IT-01 | B 注册并登录 | 收到 `login_ok` |
| IT-03 | IT-02 | A、B 加入 `general` | 双方收到加入 `system` |
| IT-04 | IT-03 | A `send_room` | B 收到 `message(scope=room)` |
| IT-05 | IT-03 | A 私聊 B | 仅 B 收到；C 收不到 |
| IT-06 | IT-02 | A 私聊离线用户 | 收到 `error(1005)` |
| IT-07 | IT-03 | 关闭 B | A 收到 B 离开 `system` |
| IT-08 | 心跳开启 | A 静默超时 | 服务端清理并广播离开 |
| IT-09 | 服务端运行 | 发送畸形 JSON | 该连接收到 `1006`，服务端存活 |

## 8. 缺陷管理

| 级别 | 定义 | 处理时限 |
|---|---|---|
| 致命 | 服务端崩溃、全员掉线 | 立即修复 |
| 严重 | 核心功能不可用（登录/聊天） | 当前迭代内 |
| 一般 | 非核心功能异常、显示问题 | 计划修复 |
| 轻微 | 文案、格式 | 择期修复 |

缺陷记录应包含：复现步骤、期望、实际、日志/原始 JSON。

## 9. 测试报告要素

- 测试范围与版本
- 环境（机器、系统、SDK 版本、网络）
- 用例执行结果（通过/失败/阻塞）
- 缺陷清单与状态
- 遗留风险与未覆盖项
- 结论（是否达到发布标准）

## 10. 联调环境要求

| 项 | 要求 |
|---|---|
| 网络 | 同一 WiFi、同一子网 |
| 主机 | 防火墙放行 TCP 9000，关闭休眠 |
| 终端 | 能 `ping` 通主机、`Test-NetConnection` 到端口 |
| 数量 | 至少 3 台（1 主机 + 2 终端） |
| 场景 | 注册/登录、群聊、私聊、切换房间、断线、心跳 |
