# 系统实现流程

> 面向项目组的端到端实现工作流：从环境准备到发布。每个阶段都有明确入口条件、
> 动作与出口标准（Gate）。阶段编号 P 与里程碑 M 一一对应（见 `DEVELOPMENT.md` §14）。

## 1. 总流程

```
P0 环境与校准 ─► P1 框架搭建 ─► P2 基础实现 ─► P3 多房间与私聊 ─► P4 健壮性与交付
                 │ 协议冻结        │                                  │
                 └────── 协议变更回环（改 §5 → 改代码 → 改测试）───────┘
```

| 阶段 | 里程碑 | 入口条件 | 出口标准（Gate） |
|---|---|---|---|
| P0 环境与校准 | M0 | 代码仓库就绪 | `cjc/cjpm` 可用，官方示例跑通，stdx 路径确认 |
| P1 框架搭建 | M1 | P0 通过 | 四文件骨架齐备，常量/数据模型/签名与 §5、§6 一致 |
| P2 基础实现 | M2 | P1 通过 | 注册→登录→`general` 群聊闭环通过（IT-01/02/04） |
| P3 多房间与私聊 | M3 | P2 通过 | 房间切换、私聊、在线列表通过（IT-03/05/06） |
| P4 健壮性与交付 | M4 | P3 通过 | 心跳/校验/单测/集成通过，三机联调通过 |

## 2. P0 环境与校准（M0）

1. 安装仓颉工具链（官方 Windows 指引，含 VS 生成工具）。
2. 验证：`cjc --version`、`cjpm --version`，记录 `Target:` 三元组。
3. 按 `DEPENDENCIES.md` 下载 stdx 并配置 `cjpm.toml`，确认导入路径。
4. 跑通官方 TCP 与 JSON 示例。

**Gate-0**：示例程序能编译、运行、收发一行数据。

## 3. P1 框架搭建（M1）

1. 建立四文件骨架与 `cjpm.toml`（见 `MINIMAL_IMPLEMENTATION.md`）。
2. 定义协议常量、错误码、限制值，与 `DEVELOPMENT.md` §5 核对。
3. 定义数据模型字段与全部函数签名，函数体为 `TODO` 占位。
4. 冻结消息类型与错误码；后续变更走“协议变更回环”。

**协议变更回环**：

```
发现协议问题 ─► 更新 DEVELOPMENT.md §5 ─► 评审确认 ─► 修改 protocol.cj ─► 更新测试
```

**Gate-1**：框架 DoD 全部满足（结构完整、签名齐全、无具体实现）。

## 4. P2 基础实现（M2）

按 `IMPLEMENTATION_PLAN.md` §2 的 M2 范围实现：

1. `protocol.cj`：编解码、分帧、字段校验，并补单元测试。
2. `server.cj`：监听、accept、连接线程、注册/登录、单房间群聊。
3. `client.cj`：连接、认证、读线程、输入循环与显示。
4. `main.cj`：参数解析与服务端/客户端分派。

**Gate-2**：两终端可注册、登录并在 `general` 互发消息（IT-01/02/04 通过）。

## 5. P3 多房间与私聊（M3）

对每个功能执行统一循环：

```
1) 读需求与协议          → 明确输入/输出/错误
2) 更新/确认协议         → DEVELOPMENT.md §5
3) 改 protocol.cj        → 常量、辅助函数
4) 实现服务端            → handler + 不变量维护
5) 实现客户端            → 命令 + 显示
6) 写/更新测试           → 单测 + 集成用例
7) 本地联调              → 多终端
8) cjfmt / cjlint / test → 质量门
9) 提交 + 评审           → 合并
```

**Gate-3**：房间与私聊需求追踪项（`IMPLEMENTATION_PLAN.md` §6）验收通过。

## 6. P4 健壮性与交付（M4）

1. 心跳（客户端 `ping`）与超时清理。
2. 字段校验完善、超长行拒绝、错误码覆盖、失败隔离。
3. 补齐单元测试；跑通集成用例 IT-01~IT-09。
4. 执行验收清单（`DEVELOPMENT_TESTING.md` §6）。
5. 更新 README 与部署说明；三机 WiFi 联调。

**Gate-4**：`cjpm test` 全绿；验收清单无未通过项；三机联调通过。

## 7. 发布交付

1. 版本号与标签：`git tag -a v1.0.0 -m "LAN Chat v1.0.0"`。
2. 归档可执行产物与运行说明。

**Gate-5**：按 README 可从零复现，三机联调通过。

## 8. 日常开发工作流

### 8.1 分支

| 分支 | 用途 |
|---|---|
| `main` | 始终可编译、测试通过 |
| `feature/*` | 功能开发 |
| `fix/*` | 缺陷修复 |
| `docs/*` | 文档 |

### 8.2 提交

`<type>(<scope>): <subject>`，type ∈ {feat, fix, docs, refactor, test, chore}。

### 8.3 质量门（每次提交前）

```powershell
cjfmt -w src
cjlint src
cjpm build
cjpm test
```

## 9. 调试流程

| 症状 | 排查顺序 |
|---|---|
| 连不上 | 服务端是否启动 → IP/端口 → 防火墙 → 是否同 WiFi/同网段 |
| 收不到消息 | 是否已 join → 服务端广播日志 → 客户端读线程是否存活 |
| 消息乱/截断 | 是否按 `\n` 分帧 → 是否处理超长行 → UTF-8 边界 |
| 卡死 | 是否持锁做 I/O → 是否存在锁顺序反转 → 是否有未解锁路径 |
| 崩溃 | 保留异常堆栈 → 定位到具体 handler → 补输入校验 |

## 10. 评审要点（合并前）

- 协议文档与 `protocol.cj` 一致
- 共享状态访问均持 `gLock`
- socket 写均持 `writeLock`
- 锁顺序为 `gLock → writeLock`，且锁内无阻塞 I/O
- 输入按 §5.9 校验，错误码正确
- 无明文密码、无敏感日志
- 通过 `cjfmt` / `cjlint` / `cjpm test`

| 测试 | 单测/集成/验收执行 |
| 全体 | 代码评审、联调、文档同步 |
