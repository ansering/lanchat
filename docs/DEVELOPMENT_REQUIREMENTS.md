# 开发需求介绍

## 1. 项目目标

LAN Chat 是仓颉语言课程设计：一台电脑在局域网中运行服务端，其他电脑运行终端客户端。服务端预先创建账号、验证登录、维护在线用户，并转发公共消息和私信。课程交付以清晰的项目规程、可继续填充的程序框架及分阶段演示为目标；当前源码是按单公共频道整理的框架，核心方法仍待实现，尚无可用聊天功能。

## 2. 角色与术语

| 名称 | 含义 |
|---|---|
| 管理员 | 在服务端本机建立、查看、禁用和重置账号的人 |
| 账号 | 管理员预先建立并发给一名使用者的登录身份，以唯一用户名标识 |
| 用户 | 持有账号并使用客户端的人 |
| 会话 | 账号成功登录后，在服务端对应的一次在线连接；同账号同时最多一个有效会话 |
| 公共频道 | 所有已登录会话自动进入的共享空间，名称固定为 `general` |
| 公共消息 | 服务端转发给公共频道所有在线会话的文字消息 |
| 私信 | 服务端只转发给发送者和指定在线账号的文字消息；客户端之间不直连 |

## 3. 必做需求

| 编号 | 需求 | 可观察的结果 |
|---|---|---|
| R1 | 管理员在服务端本机预建、查看、禁用和重置账号 | 账号保存到本地文件；重启后仍可读取；禁用账号在下次启动后不能登录 |
| R2 | 客户端使用已发放的账号登录 | 错误凭据被拒；重复登录时新会话生效、旧会话关闭 |
| R3 | 登录后自动进入唯一公共频道 | 无须手动加入；客户端可查询在线用户名 |
| R4 | 公共频道文字聊天 | 发送者和所有其他在线用户各收到一份消息 |
| R5 | `/msg <用户名> <内容>` 发送私信 | 仅双方各收到一份；第三人看不到；目标离线得到错误 |
| R6 | 维护在线会话并处理断线 | 退出或断线后在线名单更新；旧连接清理不能误删新会话 |
| R7 | 校验输入并隔离连接故障 | 非法字段、畸形 JSON、超长消息不使服务端进程退出 |
| R8 | 局域网部署与演示 | 一台服务端、至少两台客户端完成群聊和私信演示 |

管理员命令只在服务端本机运行。客户端没有自行注册、禁用用户或管理频道的权限。管理员修改账号文件前先停止服务端，修改在下次服务端启动时生效。

## 4. 选做与范围边界

文件和图片传输是选做扩展，仅在 R1–R8 验收通过后实施；图片按文件处理。当前版本不要求多房间、离线消息、桌面 GUI、跨网段通信或互联网部署。源码框架已移除旧的多房间分支；多房间不属于本次必做范围。

## 5. 质量与安全约束

- 客户端和服务端均用仓颉语言实现，使用 `cjpm` 管理工程；目标为小规模局域网课程演示。
- 一条网络消息为一行 UTF-8 JSON，单帧最多 64 KiB；文字正文最多 2000 个 Unicode 字符。具体字段见[开发方案](DEVELOPMENT_PLAN.md)。
- 账号文件不得保存明文密码；密码派生算法、随机盐来源须在 M0 校准后确定。演示账号不得复用个人真实密码。
- 当前协议为明文 TCP，局域网旁观者可能看到口令和消息；因此“私信”只表示服务端的投递范围，不保证链路保密。若课程要求链路保密，应另行增加 TLS 与证书分发。
- 状态锁保护共享数据，任何阻塞式网络读写都不在状态锁内执行；单个客户端异常不得拖垮服务端。
- 开发、测试和完成证据按[各阶段验收方案](STAGE_ACCEPTANCE.md)执行。尚未通过的项目不得标记为完成。

## 6. 交付物

交付仓颉源码与 `cjpm.toml`、本文、[开发方案](DEVELOPMENT_PLAN.md)、[各阶段验收方案](STAGE_ACCEPTANCE.md)、运行说明和测试报告。最终报告记录 SDK/stdx 版本、目标平台、局域网 IP 与端口、逐阶段结果及未解决的限制。
